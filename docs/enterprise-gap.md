# 桌面提醒：企业级能力缺口

对照对象是已经在企业里长期使用的桌面通知产品（Outlook / 飞书 / 钉钉日历提醒、Windows 通知中心策略、以及 DeskAlerts 这类集中下发的桌面告警）。下面只列当前程序还没有、或只有半成品的能力。已有的个人提醒、Cron、持久化、稍后提醒和 Mint 托盘不重复计算。

## 功能完整性

- 没有重复规则编辑器。Cron 能表达工作日和间隔，但没有「每月第几个工作日」「跳过节假日」这种企业日历语义。
- 没有完成、忽略、延期原因。弹窗只有知道了和稍后提醒，列表里分不出「已处理」和「被关掉」。
- 没有提醒分类、优先级、负责人和关联业务单号。现在只是标题加正文。
- 没有多条同时到期时的收件箱。超过 5 条会合成一条摘要，不能逐条签收。
- 没有免打扰、工作时间和按优先级突破静默。到点一律弹窗、一律按提醒自己的铃声开关播放。
- 没有跨设备同步，也没有从日历、邮件、工单系统订阅提醒。数据只在本机 JSON 文件里。
- 备份是本地另存一份 JSON，没有定时备份、恢复向导和冲突比较。

## 稳定性

- 调度在进程内。用户从托盘退出、关机、崩溃之后，错过的一次性提醒要等下次启动才补发，关机期间没有操作系统级唤醒。
- 没有看门狗。托盘线程或音频线程如果退出，主进程不会把它拉起来。
- 弹窗靠应用自己置顶。全屏会议、游戏或另一个始终置顶窗口可以挡住它，没有「必须确认才消失」的系统级强制模式。
- 铃声设备在启动时探测一次。中途拔掉耳机或切换默认声卡后，不会自动重试。

## 跨平台兼容性

- Linux 托盘分两套：Cinnamon / Xfce / MATE 走 XEmbed；KDE 和带 StatusNotifier 的桌面走 Slint 托盘。纯 Wayland 会话跳过 XEmbed，只走 StatusNotifier，并在注册失败后轮询重试；会话里始终没有 StatusNotifier 宿主（裸 wlroots 合成器）时仍然没有托盘图标，只能靠再次运行程序唤回主窗口。
- 没有签名的 Windows 安装包、macOS 公证包和 Linux 软件包。现在是一个可执行文件，发行和升级都要手工替换。
- 没有开机自启的安装选项。关进程之后要用户自己再打开。
- 多显示器已按光标所在屏幕弹出（纯 X11 会话查询全局光标；纯 Wayland 拿不到全局光标，退回主屏），但没有「记住上次屏幕」的策略。
- 高对比度、放大镜和屏幕阅读器没有做过系统级验收。控件有 accessible-label，但没有和系统高对比主题联动。

## 用户权限管理

- 没有登录、没有用户身份，也没有管理员和普通用户的区别。任何能打开这个程序的人都能改全部提醒。
- 没有配置锁定。不能由管理员下发「不允许关闭铃声」「不允许退出托盘」。
- 没有多用户隔离以外的系统账户边界。数据在当前用户的数据目录，切换用户就是另一份数据，但不能把一份提醒授权给另一个人。

## 通知策略配置

- 策略写死在程序里：弹窗不自动关闭、一次最多展开 5 条、Cron 错过的周期合并成一条。用户不能改这些阈值。
- 没有按提醒类型设置声音、是否置顶、是否允许稍后。所有提醒共用同一套弹窗。
- 没有升级路径。紧急提醒和普通提醒看起来一样，也不能在未确认时每隔几分钟再响一次。
- 稍后提醒只有 5 / 15 / 30 / 60 分钟，没有自定义时长，也没有「稍后次数上限」。

## 日志审计

- `app.log` 只记本机的启动、触发、保存、删除和托盘失败，超过 1 MB 会改名，没有签名，也没有防篡改。
- 日志里没有操作者，因为没有用户身份。不能回答「谁把这条提醒删了」。
- 不能按提醒导出一段审计历史，也不能把日志交到集中式日志系统。
- 弹窗上的「知道了」和「稍后」会写日志，但没有保留用户点的是哪一个时长以外的更多上下文（例如当时在哪块屏幕、是否被全屏挡住）。

## 异常容错

- JSON 主文件损坏时会改用 `.bak`，两份都坏就停止写入并留下 `.broken`。这能避免覆盖，但界面只有一行提示，没有引导用户选择备份恢复。
- 数据文件版本比程序新时拒绝保存。没有「只读查看」和「导出后升级」的明确流程。
- 自定义铃声文件被删或解码失败时会退回默认提示音，弹窗上没有单独说明这次为什么没有用用户选的文件。
- 单实例锁依赖文件锁。异常断电后锁会随进程消失，这一点是安全的；但如果数据目录在网络盘上，文件锁行为没有验证。

## 建议的后续顺序

1. 开机自启、安装包和签名，先让程序在三端都能被企业桌面标准流程部署。
2. 通知策略页：免打扰、声音设备重试、同时弹窗条数、稍后次数上限。这些不需要服务器。
3. 提醒状态补全：待处理、已确认、已稍后，并在日志里记下确认动作。
4. Wayland 托盘和「在指针所在屏幕弹出」。
5. 账户、下发和审计要等有服务端之后再做，不适合继续堆在单机 JSON 上。
